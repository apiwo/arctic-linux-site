Arctic is a linux distribution built from source, pairing a BSD userland (toybox, zsh, doas, netbsd-curses, bmake) with glibc underneath. busybox handles init. packages install through alpm, its own package manager, with per-file verification and one-command rollback built in. installed declaratively: edit a config file, run one command. a musl libc build exists alongside the glibc build — same userland, same alpm, smaller static binaries and no dynamic linker gymnastics. pick one at install time. see the docs for the tradeoffs.

features

  • toybox userland in place of GNU coreutils, zsh as the login shell
  • declarative install and system management — arctic-strap, arctic-rebuild, no menus
  • doas instead of sudo, netbsd-curses instead of ncurses
  • alpm: rollback, -nomod staging, per-file sha256 verification, alt-nonfree counterparts for every proprietary package
  • NVIDIA, AMD, and Intel drivers coexisting through libglvnd
  • glibc and musl builds, both drawing from the same 500+ package manifest
  • boots to a TTY — no display manager, no desktop, install one afterwards with alpm

glibc vs musl

both builds run the same toybox/zsh/alpm userland and are driven by the same manifest in arctic-linux-ports — switching libc doesn't mean switching distros.

glibcmusl
binary sizelarger, dynamic by defaultsmaller, static-friendly
compatwidest package/proprietary-blob compata few packages need patching or aren't ported yet
NSS / DNSfull NSS, glibc resolvermusl's own minimal resolver, no NSS plugins
use casedaily driver, NVIDIA/proprietary-heavycontainers, minimal installs, static toolchains

install with A_LIBC=musl in install.conf, or leave it unset/glibc for the default. alpm resolves the right package variant automatically based on which build you're on.

STATUS: arctic-minimal boots and installs end to end on glibc — Limine → kernel → initramfs → busybox init → zsh, with alpm installing from the repository carried on the medium. the musl build boots too but has a smaller slice of the package manifest ported so far. no desktop image exists yet on either libc, by design. the fully declarative install/rebuild flow is still in testing and has known bugs — core install works, but expect rough edges until it's ironed out.

install

# wired is automatic, for wireless:
iwctl station wlan0 connect YOUR-NETWORK

# edit the config, then one command does everything
# set A_LIBC=musl for the musl build, or leave it as glibc
vi /etc/arctic/install.conf
arctic-strap

set A_DISK=/dev/sdX in the config and that one command partitions, formats, mounts, installs, and wires up the bootloader. leave it commented out for the manual mount-it-yourself path instead. full walkthrough in the docs.

build it yourself

every build runs sandboxed under bubblewrap — the host is mounted read-only, only the build tree and /tmp are writable. that is not a formality: a recipe that forgets DESTDIR once installed glibc straight over a host's /usr/lib. it now just fails with EROFS instead. pass --libc=musl to build the musl variant instead of the glibc default.

build/arctic-sandbox --check
build/build.sh # or: build/build.sh --libc=musl

contribute

500+ packages are defined in a manifest in arctic-linux-ports, with recipes generated from it rather than hand-written. adding a port means adding a line to the manifest, not boilerplate — most recipes build clean on both libc targets with no changes needed. porting a package to musl that only builds on glibc is one of the easiest ways to help right now.
