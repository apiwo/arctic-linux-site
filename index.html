Arctic is a linux distribution built from source, pairing a BSD userland (toybox, zsh, doas, netbsd-curses, bmake) with glibc underneath. packages install through alpm, its own package manager, with per-file verification and rollback built in.

the machine is described in a file, and one command makes the machine match it. every rebuild records a generation — the packages, services and config as they were — so a bad edit is one arctic rollback away, or one entry in the boot menu if the result will not boot. the same idea as NixOS, built on an ordinary package manager rather than replacing it.

the kernel is its own fork of Linux LTS with the ZEN patchset on top. init is your choice — busybox, OpenRC, sysvinit, runit, dinit, s6, systemd — and services are declared once and translated to whichever one runs. musl exists alongside glibc as an opt-in second libc. see the docs.

features

  • declarative: one config file describes the machine, arctic-rebuild makes it so — no menus anywhere
  • generations: every rebuild is recorded and undoable, from the shell or the boot menu
  • Arctic-kernel — Linux 6.12 LTS + ZEN (PDS/BMQ, ACS override, ntsync, vhba), alongside five other kernel choices
  • pick your init: busybox, OpenRC, sysvinit, runit, dinit, s6-66, systemd — services declared once, translated to each
  • toybox userland in place of GNU coreutils, zsh as the login shell, doas instead of sudo, netbsd-curses instead of ncurses
  • alpm: rollback, -nomod staging, per-file sha256 verification, alt-nonfree counterparts for every proprietary package
  • desktop profiles — XFCE, KDE, Niri, dwm — and a sound profile that installs the whole PipeWire stack working
  • btrfs subvolumes and snapshots, LUKS2 encryption, install onto a whole disk or partitions you made yourself
  • NVIDIA, AMD, and Intel drivers coexisting through libglvnd
  • glibc with musl available alongside it, both from the same 530+ package manifest

glibc vs musl

both builds run the same toybox/zsh/alpm userland and are driven by the same manifest in arctic-linux-ports — switching libc doesn't mean switching distros.

glibcmusl
binary sizelarger, dynamic by defaultsmaller, static-friendly
compatwidest package/proprietary-blob compata few packages need patching or aren't ported yet
NSS / DNSfull NSS, glibc resolvermusl's own minimal resolver, no NSS plugins
use casedaily driver, NVIDIA/proprietary-heavycontainers, minimal installs, static toolchains

musl installs alongside glibc rather than instead of it — alpm ins musl puts it at /usr/musl and glibc stays what the base system is built against. binary packages are glibc; on musl you build from source with alpm ins -s.

STATUS: the base image boots and installs end to end — Limine → kernel → initramfs → init → zsh, with alpm installing from the repository carried on the medium. the declarative layer (system.conf, arctic-rebuild, generations, rollback) works and is tested, though system.conf currently covers packages and services rather than hostname/locale/users. init systems other than busybox generate correct service definitions but have had much less real use — use the default for a first install. musl is real but young: musl itself and a handful of packages build against it. no desktop ISO exists, by design; desktops install afterwards from a profile.

install

# wired is automatic, for wireless:
iwctl station wlan0 connect YOUR-NETWORK

# edit the config, then one command does everything
nano /etc/arctic/install.conf
arctic-strap

set A_DISK=/dev/sdX and that one command partitions, formats, mounts, installs and wires up the bootloader. or set A_ROOT_PART/A_BOOT_PART to use partitions you made yourself, formatted or not. the config is checked before anything is written — it either says Config file accepted with a summary, or lists everything that is wrong and stops having changed nothing. arctic-strap takes no arguments; the disk is in the config. full walkthrough in the docs.

build it yourself

every build runs sandboxed under bubblewrap — the host is mounted read-only, only the build tree and /tmp are writable. that is not a formality: a recipe that forgets DESTDIR once installed glibc straight over a host's /usr/lib. it now just fails with EROFS instead.

build/arctic-sandbox --check
build/build.sh

musl packages build through build/arctic-musl-sandbox, which adds a real musl toolchain at /usr/musl inside the same read-only sandbox.

contribute

530+ packages are defined in a manifest in arctic-linux-ports, with recipes generated from it rather than hand-written. adding a port means adding a line to the manifest, not boilerplate — most recipes build clean on both libc targets with no changes needed. porting a package to musl that only builds on glibc is one of the easiest ways to help right now.
