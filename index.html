Arctic is a linux distribution built from source, pairing a BSD userland (toybox, zsh, doas, netbsd-curses, bmake) with glibc underneath. packages install through alpm, its own package manager, with per-file verification and rollback built in. every repository index is signed with signify, and the key that checks it ships in the base system rather than arriving beside the thing it verifies.

the machine is described in a file, and one command makes the machine match it. every rebuild records a generation — the packages, services and config as they were — so a bad edit is one arctic rollback away, or one entry in the boot menu if the result will not boot. the same idea as NixOS, built on an ordinary package manager rather than replacing it.

the kernel is its own fork of Linux LTS with the ZEN patchset on top. init is your choice — initialization, OpenRC, sysvinit, runit, dinit — and services are declared once and translated to whichever one runs. see the docs.

features

  • declarative: one config file describes the machine, arctic-rebuild makes it so — no menus anywhere
  • generations: every rebuild is recorded and undoable, from the shell or the boot menu
  • Arctic-kernel — Linux 6.12 LTS + ZEN (PDS/BMQ, ACS override, ntsync, vhba), alongside five other kernel choices
  • pick your init: initialization, OpenRC, sysvinit, runit, dinit — services declared once, translated to each
  • toybox userland in place of GNU coreutils, zsh as the login shell, doas instead of sudo, netbsd-curses instead of ncurses
  • alpm: rollback, -nomod staging, per-file sha256 verification, alt-nonfree counterparts for every proprietary package
  • desktop profiles — XFCE, KDE, Niri, dwm — and a sound profile that installs the whole PipeWire stack working
  • btrfs subvolumes and snapshots, LUKS2 encryption, install onto a whole disk or partitions you made yourself
  • NVIDIA, AMD, and Intel drivers coexisting through libglvnd
  • alpm system fix — corrections that no version bump would carry, applied as ordinary binary packages

STATUS: alpha. the image boots and installs end to end — Limine → kernel → initramfs → init → zsh — fetching packages from the online repositories rather than carrying them on the medium, so an install is current the day you run it rather than the day the image was built. the declarative layer (system.conf, arctic-rebuild, generations, rollback) works and is tested, though system.conf currently covers packages and services rather than hostname/locale/users. init systems other than the default generate correct service definitions but have had much less real use — use the default for a first install. no desktop ISO exists, by design; desktops install afterwards from a profile.

install

# wired is automatic, for wireless:
iwctl station wlan0 connect YOUR-NETWORK

# edit the config, then one command does everything
nano /etc/arctic/install.conf
arctic-strap

set A_DISK=/dev/sdX and that one command partitions, formats, mounts, installs and wires up the bootloader. or set A_ROOT_PART/A_BOOT_PART to use partitions you made yourself, formatted or not. the config is checked before anything is written — it either says Config file accepted with a summary, or lists everything that is wrong and stops having changed nothing. arctic-strap takes no arguments; the disk is in the config. full walkthrough in the docs.

build it yourself

every build runs sandboxed under bubblewrap — the host is mounted read-only, only the build tree and /tmp are writable. that is not a formality: a recipe that forgets DESTDIR once installed glibc straight over a host's /usr/lib. it now just fails with EROFS instead.

build/arctic-sandbox --check
build/build.sh

the toolchain is clang, lld and the llvm-* binutils. there is no second one: a package built by gcc is not an Arctic package, and alpm build refuses to produce one unless it is told, loudly, that you know what you are doing.

llvm is a package now, so an installed machine has a compiler of its own and alpm ins -s works on it. at 148 MiB it is far past what a git mirror will hold, so it arrives the same way firmware does — a release asset, indexed by the big repository, installed like anything else.

be straight about where this has got to: the packages in the current image were still compiled by gcc. llvm being packaged is what makes the rebuild possible, not the rebuild itself.

contribute

530+ packages are defined in a manifest in arctic-linux-ports, with recipes generated from it rather than hand-written. adding a port means adding a line to the manifest, not boilerplate. getting a package that assumes gcc to build under clang is one of the easiest ways to help right now.

pull requests welcome on github.
